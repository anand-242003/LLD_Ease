# Phase 32 — Remove the Brief Dialog

[⟵ Index](../PHASES.md) · [PRD.md](../PRD.md) · [DESIGN.md](../DESIGN.md) · [← Phase 31](./31.problem-context-sidebar-panel.md) · [Phase 33 →](./33.consolidate-solution-access.md)

## 1. Relationship to Previous Phase

**Depends on:** [Phase 31 — Problem Context Sidebar Panel](./31.problem-context-sidebar-panel.md)

Now that the sidebar shows a problem's title, description, and requirements persistently, the `Brief` modal in `PracticeBanner` shows nothing the user can't already see without opening it. This phase removes it.

**What the next phase assumes:** Phase 33 assumes `PracticeBanner` has already lost its `Brief` button, so it is only dealing with the banner's remaining two controls (`Reveal reference`, `Exit`) when it consolidates solution access.

---

## 2. Overview

**Goal:** delete the `Brief` button and its modal dialog from the Practice banner.

**Supersedes:** `PRD.md` §9.5's in-session sub-flow table row for `Brief`, and §10.4.1's banner content list (`PRACTICE` pill, title, subtitle, spacer, `Brief`, `Reveal reference`, `Exit` → drops `Brief`). Note that `PRD.md` §27-U11 itself rates this feature "Confidence: Low" ("Does the Brief open a modal or expand the banner?") — it was already the weakest-evidenced part of the original spec, which is exactly why replacing it with something more directly observed to work (the Phase 31 panel) is a safe call.

**From the user's perspective, why this is worth doing:** a modal that repeats information already visible to your left is not a convenience, it's a tax — one more thing to open and close, one more moment where the canvas you're mid-thought on gets covered up. Once Phase 31 shipped, `Brief` stopped teaching the user anything new; it just became a second, slower way to see the same text. Removing it is pure simplification: same information, fewer clicks, less UI to maintain.

## 3. What to Build

**Files to delete:** `src/components/library/BriefDialog.tsx` — confirmed (Phase 31's research) to have exactly one consumer, `PracticeBanner`; safe to delete outright.

**Files to modify:** `src/components/canvas/PracticeBanner.tsx`.

**Step-by-step:**
1. Remove the `Brief` button from `PracticeBanner` and the `showBrief` local state that toggled it.
2. Remove the conditional `<BriefDialog problem={problem} onClose={...} />` render.
3. Delete `BriefDialog.tsx`.
4. The banner's content now reads, left to right: `PRACTICE` pill → title → subtitle → spacer → `Reveal reference` → `Exit`. Re-check horizontal spacing/padding now that one button is gone — do not leave a wider-than-needed gap where `Brief` sat; let the button group's `gap` naturally close up per the existing flex layout (`display:flex; align-items:center; gap:16px` from `DESIGN.md` §10.4.1's original recipe).
5. Confirm the banner's subtitle line is still useful as a lightweight glance-reminder of which problem you're on (it stays — only the modal it used to open is gone).

## 4. UI & Design Requirements

**Relevant DESIGN.md sections for this phase:** the existing `PracticeBanner` recipe (`PRD.md` §10.4.1, described as an observed layout — this phase updates it by removing one button, not by redesigning the banner).

**UI consistency checklist:** banner remains centered, teal-bordered, same padding/radius as before; button group re-flows without a dead gap; `Reveal reference` remains the sole emphasized (teal outline) button in the banner.

## 5. Testing Framework

> No automated test files are added in this phase (or any phase in this set) — see `PHASES.md` §0.2 / §0.9. All verification below is manual: drive the running app for black-box checks, inspect `window.__store` for white-box checks.

### Black-Box Testing (User Simulation)

**Verification — Black-box:**
1. Start a Practice session on any problem. **Expected:** the banner shows `PRACTICE` pill, title, subtitle, `Reveal reference`, `Exit` — no `Brief` button anywhere.
2. Confirm the sidebar panel from Phase 31 is now the only place the problem's full description and requirements are readable during practice.
3. Confirm no console error or broken import results from the deletion (a stray reference to `BriefDialog` would throw at build time, which is the fastest signal something was missed).

### White-Box Testing (Internal State Inspection)

**Verification — White-box:**
1. Repo-wide search for `BriefDialog` and `showBrief` returns zero remaining references in `src/`.

### Definition of Done (Exit Criteria)

**Definition of Done:** `Brief` is unreachable and its component file no longer exists; the banner renders correctly with its remaining two buttons; no information available via the old `Brief` modal is now unreachable anywhere in the app (it must still be visible via the Phase 31 sidebar panel).

### Scope Boundaries — Do NOT

**Do NOT:** touch `Reveal reference` or `Exit` yet (Phases 33 and 34 respectively) — this phase removes exactly one control and its backing component.
