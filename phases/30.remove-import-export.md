## 2. Overview

**Goal:** remove the Import and Export features entirely — every button, menu, dropdown, hidden file input, keyboard shortcut, hook, and helper that implements them — per the user's direct request to cut this feature.

**Supersedes:** `PRD.md` §9.12 (Flow: Export) and §9.13 (Flow: Import), the `Export`/`Import` rows in `PRD.md` §2.4/Appendix B and the document-permission table in §8.2, and Phase 26 (`Export / Import / Clear`) — Phase 26's *Clear* half is unaffected and stays exactly as built; only its Export/Import half is undone.

**From the user's perspective, why this is worth doing:** ClassForge exists to run one loop — model, get linted, get scored, improve (`PHASES.md` §0.8). Export/Import serves a *different* job (getting a diagram in or out of the browser) that the app's actual users — people practicing for an interview — essentially never need: they aren't sharing diagrams with teammates or round-tripping files between machines mid-practice. What the feature *does* cost every user, whether they ever touch it or not: two more header buttons (plus their mobile-menu duplicates) to visually parse before reaching `LLD Problems`/`Score my solution`, a hijacked `Cmd/Ctrl+S` that surprises anyone used to that shortcut doing something else in their browser, and a whole confirm-dialog/dropdown-menu code path to keep bug-free for a feature that isn't core to the product's value. Removing it is a net simplification with no loss to the actual practice loop.

## 3. What to Build

**Files to delete:** `src/hooks/useExport.ts`, `src/hooks/useImport.ts`, `src/lib/download.ts` (confirm with a repo-wide search that nothing besides these two hooks and `useKeyboardShortcuts.ts` imports it before deleting — if something else depends on `sanitizeFilename` or a download helper for an unrelated feature, keep `download.ts` and delete only the dead parts).

**Files to modify:** `src/components/layout/AppHeader.tsx`, `src/hooks/useKeyboardShortcuts.ts`, `package.json`.

**Step-by-step:**
1. In `AppHeader.tsx`: remove the desktop `Export` button, its dropdown menu (`export-dropdown-menu`, the PNG/SVG/JSON items), the desktop `Import` button and its hidden `<input type="file">`, the `Replace diagram` `ConfirmDialog` instance that gates Import-over-existing content, and every duplicate of these four inside the mobile hamburger menu. Remove the now-unused `useExport`/`useImport` hook imports and any local state that only existed to drive them (dropdown-open flag, confirm-dialog-open flag, file-input ref).
2. In `useKeyboardShortcuts.ts`: remove the `Cmd/Ctrl+S` binding entirely — do not repurpose it and do not leave a `preventDefault()`-only no-op in its place. A shortcut that silently swallows the browser's native behavior while doing nothing is worse than no shortcut at all; if there is a shortcuts-reference UI built in Phase 27, remove its `Cmd/Ctrl+S → Export` row too.
3. Delete `useExport.ts`/`useImport.ts`/`download.ts` per the confirmation step above.
4. Run `npm uninstall html-to-image` (it was only ever consumed by `useExport.ts`'s PNG/SVG rendering) and confirm `package.json`/`package-lock.json` no longer list it.
5. Re-flow the remaining header buttons (`LLD Problems`, `Clear`, `Score my solution` when in Practice, `Buy me a coffee`) so there is no leftover gap where Export/Import sat — this is a spacing fix, not a redesign; use the existing `--sp-*` tokens, don't invent new ones.
6. Leave everything else — `Clear`, `Sample`, `PracticeBanner`, the Problem Library — untouched. Sample is handled in Phase 33, not here.

## 4. UI & Design Requirements

**Relevant DESIGN.md sections for this phase:** §5.1 (Button), §4 (Spacing), §10 (Consistency Audit).

**UI consistency checklist:** header button group re-centers/re-spaces cleanly with two (desktop) and their mobile-menu duplicates removed; no orphaned divider or icon-only gap remains; mobile hamburger menu no longer lists `Export PNG image` / `Export SVG vector` / `Export JSON (reloadable)` / `Import JSON`.

## 5. Testing Framework

> No automated test files are added in this phase (or any phase in this set) — see `PHASES.md` §0.2, restated in §0.9 as a deliberate project-specific convention. All verification below is manual: drive the running app for black-box checks, inspect `window.__store` (or an ephemeral, deleted-after-use scratch script) for white-box checks.

### Black-Box Testing (User Simulation)

**Verification — Black-box:**
1. Load the app at desktop width. **Expected:** header shows `LLD Problems`, `Clear`, `Buy me a coffee` (and `Score my solution` only in Practice mode) — no `Export` or `Import` button anywhere.
2. Open the mobile hamburger menu (or resize to mobile width). **Expected:** no Export/Import rows.
3. Press `Cmd/Ctrl+S` anywhere in the app. **Expected:** nothing happens in-app (the browser's own native Save-Page behavior, if any, is unaffected — the app no longer intercepts the combo at all).
4. Confirm no dangling "Replace diagram?" confirm dialog can be triggered from anywhere.

### White-Box Testing (Internal State Inspection)

**Verification — White-box:**
1. Repo-wide search for `useExport`, `useImport`, `html-to-image` returns zero remaining references in `src/`.
2. `package.json` no longer lists `html-to-image` as a dependency.
3. `window.__store.getState()` contains no export/import-related UI flags left over from removed local state.

### Definition of Done (Exit Criteria)

**Definition of Done:** Export and Import are unreachable from every surface (desktop header, mobile menu, keyboard shortcut); the dead code and dependency are physically removed, not just hidden; `Clear` and every other header control still work exactly as before.

### Scope Boundaries — Do NOT

**Do NOT:** touch the `Sample` button (Phase 33) or `Clear` (unaffected, stays); do not repurpose `Cmd/Ctrl+S` for anything else in this phase; do not remove `serialize`/`deserialize` from `src/domain/serialization` if anything else in the app (e.g. persistence) still depends on them — only the Export/Import-specific UI wiring and file-download plumbing are in scope.
