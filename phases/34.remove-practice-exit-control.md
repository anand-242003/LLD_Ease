## 2. Overview

**Goal:** remove the `Exit` button from the Practice banner — confirmed (Phase 31's research) to be the **only** "exit"-style control anywhere in the codebase (`src/components/canvas/PracticeBanner.tsx`, `handleExit` → `endPractice()`).

**Supersedes:** `PRD.md` §9.5's in-session sub-flow table row for `Exit`, and its stated behavior ("Ends the session: banner disappears... diagram is kept"). §12.5's practice-session state machine is amended: the *only* remaining transition out of an active session is starting a different one (already gated by the existing confirm-and-replace guard from §9.5's edge cases), not an explicit dismiss action.

**From the user's perspective, why this is worth doing:** `Exit` sits immediately next to `Reveal reference` (now the sidebar action, but structurally the same position in the banner) — it's an easy button to hit by accident while reaching for something else, and its actual effect (quietly clearing the practice flag while *keeping* your diagram) is subtle enough that a learner who fat-fingers it may not immediately notice their "Score my solution" button vanished and wonder why. Every other piece of state in this app — the active document, the right-panel tab, notes, ink, viewport — already persists silently in the background with no "exit" gesture required; a practice session should behave the same way. It should simply stay active until the learner deliberately starts a *different* one, which already has its own well-designed confirm-and-replace guard. Removing `Exit` removes an easy mis-click and a small, needless decision point, without taking away any real capability — a learner who's done with a problem just opens the library and starts the next one.

## 3. What to Build

**Files to modify:** `src/components/canvas/PracticeBanner.tsx`.

**Step-by-step:**
1. Remove the `Exit` button and its `handleExit` handler.
2. The banner now contains only: `PRACTICE` pill → title → subtitle. No trailing button group at all.
3. Re-size the banner's container to hug this simpler content rather than keeping the previous ~700px fixed width now that there is nothing to right-align against — shrink it to a comfortable content-width card (still centered, still the same padding/radius/border treatment), so it doesn't look like it's missing something rather than deliberately simplified.
4. Confirm the practice-session state machine now has exactly one way to end/replace a session: starting a *different* Practice session from the Problem Library, which already triggers the existing "Start practising `<Problem>`? Your current design will be cleared." confirm-and-replace guard (`PRD.md` §9.5). This guard is unaffected by this phase and must continue to work exactly as before.
5. `endPractice()` itself can stay in `practiceSlice.ts` if anything else internally still calls it (e.g. the replace-session flow may call it before starting the new one) — only the **UI trigger** for calling it standalone is removed. Do not delete the action if it's still a legitimate internal step of "replace this session with a new one."

## 5. Testing Framework

> No automated test files are added in this phase (or any phase in this set) — see `PHASES.md` §0.2 / §0.9. All verification below is manual: drive the running app for black-box checks, inspect `window.__store` for white-box checks.

### Black-Box Testing (User Simulation)

**Verification — Black-box:**
1. Start a Practice session. **Expected:** the banner shows only `PRACTICE` pill, title, and subtitle — no buttons at all.
2. Reload the page mid-session. **Expected:** the banner and session are restored exactly as before (unaffected regression check — persistence doesn't depend on how the session used to be exited).
3. While practicing Problem A, open the Problem Library and click `Practice` on Problem B. **Expected:** the existing "Start practising Problem B? Your current design will be cleared." confirm dialog still fires; confirming replaces the session and banner correctly; canceling leaves Problem A's session untouched.

### White-Box Testing (Internal State Inspection)

**Verification — White-box:**
1. Repo-wide search for an "Exit" button/handler in `src/components/canvas` returns zero remaining references.
2. `window.__store.getState().practiceSession` behaves identically to before this phase in every scenario except that there is no longer a UI action that sets it to `null` without replacing it with a new session.

### Definition of Done (Exit Criteria)

**Definition of Done:** no `Exit` control exists anywhere; a practice session persists until a new one replaces it; the existing replace-session confirm guard is unaffected; the banner renders correctly at its new, simpler width.

### Scope Boundaries — Do NOT

**Do NOT:** invent a new way to "leave practice mode" to compensate — the point of this phase is that no explicit exit gesture is needed; do not delete `endPractice()` if the replace-session flow still legitimately calls it internally.
